**Decisions for the brainstorm:**
* **8-A, the redirect host (blocker for the roadmap as written).** The Google console refuses `https://mespapiers.local/api/auth/google/callback`: a redirect host's TLD must be on the public suffix list, and only `localhost` is exempt (`CLAUDE.md`, *Gotchas*). Options: (a) `https://localhost/api/auth/google/callback` through nginx on 443: no new infra, but Google sign-in is then tested on `localhost`, against the *test on mespapiers.local* rule, and the state cookies are per host, so the flow must start on `localhost` too; (b) a wildcard-DNS name such as `mespapiers.127.0.0.1.nip.io` (or sslip.io): one host for everything, but needs an nginx `server_name`, a cert for it and `allowedDevOrigins`, and a third-party DNS service at the defence; (c) a real domain pointed at 127.0.0.1. In every case `APP_URL` must be the host the browser is on.
* **8-B, deleting an OAuth-only account** (owed since 2026-10-12): what such a user confirms with instead of a password (typing their email, or a fresh provider sign-in). It lands no later than phase 8's PR, in Amir's file with his review, so agree with him first.
* **8-C, `email_verified`.** The roadmap refuses unverified emails only for GitHub (phase 9). Google sends `email_verified`; linking on an unverified address is the same takeover, so 8.4 should refuse it too.
* **8-D, the display name** of a created user: Google's `name` can be missing or fail `displayNameField`'s length rule. Pick the fallback (e.g. the email's local part, cut to the limit).
* **8-E, ID token or userinfo.** The token exchange returns an `id_token`; received straight from Google's token endpoint over TLS, it may be decoded without a signature check (OIDC Core §3.1.3.7), checking `iss` and `aud`. Or call the userinfo endpoint. Neither needs a dependency.

### Phase 2 lessons worth keeping
* Actions redirect with `return redirect({ href, locale: await getLocale() })` from `@/i18n/navigation`; the `return` is needed because TS doesn't treat the destructured `redirect` as `never`.
* React 19 resets uncontrolled fields after a form action, so email and display name are controlled inputs; the password is left to be cleared.
* `vitest.config.mts` has `server.deps.inline: ["next-intl"]` (its extensionless `next/navigation` import breaks Node ESM).
* CSRF (C11) is Next's built-in Server Action Origin/Host check. Evidence: a login replayed with `Origin: https://evil.example` is aborted and creates no Session row. Full steps in `docs/testing-auth.md`.
* Dev-only noise, not bugs: `Cannot write to a CLOSED writable stream` after an out-of-browser action POST; `PrismaClientInitializationError` during build with the musl-only client.
* A stale `.next/dev/types` (from before the `[locale]` move) breaks `npm run build`'s typecheck; delete it, `next dev` regenerates it.
