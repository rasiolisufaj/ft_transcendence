# Phase 12 — Profile, Avatar, Friends' Online Status (D14) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Any signed-in user opens anyone's profile (unless a block stands between them) and can send them a friend request from it, edits their own display name, uploads an avatar (initials when there is none), and sees which of their friends are online. These are the four lines of the user-management major that phases 0–4 did not cover (roadmap §C-22).

**Architecture:** One new page, `/[locale]/users/[id]`, which shows the edit forms only on your own profile. Two Server Actions sit next to it. One Route Handler serves the avatar. One small module, `src/lib/users/profile.ts`, holds the relation between two users and the online rule. One migration adds `User.lastSeenAt` and a `UserAvatar` table. Online status is *last seen*: `validateSessionToken()` stamps `lastSeenAt` at most once a minute, and "online" means seen in the last 5 minutes. Live presence is a later hand-off to the realtime server, and `lastSeenAt` stays as the state at page load. The published `SessionContext` does not change.

**Tech Stack:** Next.js 16 (Server Actions, Route Handlers, `next/image` `unoptimized`) · React 19 `useActionState` · Prisma 6 (`@/generated/prisma/client`) · Zod 4 (`z.file()`) · Vitest against the dev Postgres · `next-intl` · the browser's canvas API (no new dependency)

## Data flow

- **Opening a profile:** `requireUser()` → `prisma.user.findUnique({ where: { id }, select: { id, displayName, email, createdAt, lastSeenAt, avatar: { select: { updatedAt: true } } } })` (null → `notFound()`) → unless it is the viewer's own id, `relationBetween(viewer, id)` (`blocked` → `notFound()`) → render. The email is rendered only on your own profile, and the dot only for a `friend`; the RSC payload carries nothing else. The avatar's `src` is `/api/users/<id>/avatar?v=<updatedAt in ms>`: after an upload, `refresh()` re-renders the page, and only a changed `src` makes the browser fetch the new image.
- **Saving the name:** the form → `updateProfile(prev, formData)` → `profileSchema.safeParse` (errors → `{ fieldErrors }`) → `prisma.user.update({ where: { id: ctx.user.id }, data: { displayName } })` → `revalidatePath` so the nav shows the new name → `{ saved: true }`. The action never reads an id from the form.
- **Uploading an avatar:** the file input (`accept` = `AVATAR_TYPES`) → canvas re-encode (256 × 256 PNG; a file the browser cannot decode shows `avatarType` and is not sent) → `uploadAvatar(prev, formData)` → `avatarSchema` (size) → `sniffMime(bytes)` must be `image/png`, `image/jpeg` or `image/webp` → `prisma.userAvatar.upsert({ where: { userId: ctx.user.id }, … })` → `revalidatePath`.
- **Adding a friend from a profile:** the button (a plain `<form>`, the profile's id in a hidden `userId`) → `addFriendFromProfile(formData)` → `isUserId` → `sendRequest(ctx.user.id, userId)` (Alexandre's: refuses yourself and a block in either direction, ignores a repeat, accepts the other person's pending request) → `refresh()`, so the button turns into *Demande d'ami en attente*. The requester always comes from the session.
- **Being seen:** any signed-in request → `validateSessionToken()` → if `lastSeenAt` is null or older than 60 s, `prisma.user.updateMany({ where: { id }, data: { lastSeenAt: now } })`. Logout → `lastSeenAt: null`.

## Live upgrade (hand-off, not built here)

When Alexandre's realtime work reaches presence (D3), the dot goes live without changing anything else in this phase:

1. **Contract** (`src/contracts/events.ts`, Alexandre): add plan §5's `{ type: "presence.changed"; userId: string; online: boolean; at: string }` to `RealtimeEvent`, routed to a user topic.
2. **Server** (`src/realtime/`, Alexandre): when a user's **first** socket opens, and when their **last** one closes, publish `presence.changed` to `user:<friendId>` for each accepted friend (one `Friendship` query, as `isChannelMember` does in PR #36). Also write `lastSeenAt` on connect, on each heartbeat at most once a minute, and on the last disconnect, so an idle open tab still counts as seen and **`lastSeenAt` stays a correct initial state**.
3. **Client** (Rasiol): the dot becomes a client component that takes `initialOnline` (computed from `lastSeenAt` on the server, as now) and switches on `presence.changed` events for that user, through D5's hook.

`isOnline()`, the column and the write in `validateSessionToken()` all stay. The `ponytail:` comment on `ONLINE_WINDOW_MS` points here.

## Error handling

- User mistakes (a bad name, no file, a wrong type, too big) return `{ fieldErrors }` / `{ error }` with i18n keys and change nothing. They never throw.
- An unknown or blocked profile is a 404 (`notFound()`), the same answer for both, so a block is not revealed.
- The avatar route answers with status codes only (401, 404, 200), with no body on errors.
- The `lastSeenAt` write cannot fail a request because of a vanished user (`updateMany`).
- A file the browser cannot decode for the re-encode (a PDF, an iPhone HEIC photo in Chrome) shows `profile.errors.avatarType` and is not sent.

## Global Constraints

Every task's definition of done includes this section.

- Import Prisma from `@/generated/prisma/client`, never `@prisma/client`. Use the `prisma` singleton from `src/lib/db.ts`.
- Each form has **one Zod schema module imported by both the client component and the server action** (plan §0): here `src/lib/users/schemas.ts`.
- Every user-visible string is a `next-intl` key. Add it to `messages/fr.json` first (it types `t()`), then `en.json` and `es.json`. `npm run i18n:check` only sees literal `t("key")` calls and `` t(`prefix.${x}`) `` templates, and only through a `const t = useTranslations("ns")` / `getTranslations("ns")` binding written on one line.
- Import `Link` from `@/i18n/navigation`; `notFound` from `next/navigation`.
- Pages that query Prisma at request time set `export const dynamic = "force-dynamic"`.
- A new primitive in `src/components/ui/` also goes into the gallery at `src/app/[locale]/dev/ui/page.tsx`.
- Uploads are checked by **magic bytes**; files are served only through an authorised route, with `Cache-Control: private, no-store` (plan §2).
- Every Prisma model has `createdAt` and `updatedAt`. Timestamps are stored in UTC and rendered in `Europe/Paris` (next-intl's `timeZone` does it).
- The published `SessionContext` does not change.
- Zero ESLint warnings. Zero console errors or warnings on every route. Responsive and keyboard-navigable at 375 / 768 / 1440.
- Conventional Commits (`feat(profile): …`). **No commit without Rasiol's go-ahead**; stage by path, never `git add -A`.
- DB tests hit the real Postgres from `.env`. Each creates its own `test-<uuid>@mespapiers.test` users and deletes them afterwards (`Session`, `Friendship` and `UserAvatar` cascade from `User`).
- If DB tests fail with `could not locate the Query Engine for runtime "debian-openssl-3.0.x"`, the `web` container regenerated the client: `docker exec mespapiers_web chown -R $(id -u):$(id -g) /app/src/generated && npm run db:generate` (`CLAUDE.md`, *Prisma engine flips*).

## Review Focus

Inputs the design implies but no unit test exercises, most likely to bite first. Each one has its check in the task that owns the code.

1. **A malformed profile id** (`/fr/users/%00`, a NUL byte in the URL): Postgres rejects a NUL in a text parameter, so the query throws and the page is a 500. Expected: a 404. Owned by Task 1 (`isUserId`, used by the page; Task 5's route test pins it on the avatar route).
2. **A new avatar after an upload:** `refresh()` re-renders the page, but an `<img>` whose `src` did not change is not fetched again, so the old picture stays until a full reload. Expected: the new one at once. Owned by Task 5 (`?v=<updatedAt>` on the `src`; its browser step).
3. **A portrait phone photo:** a camera stores the picture sideways plus an EXIF orientation tag, and the re-encode drops the tag. Expected: an upright avatar (browsers apply the orientation when they draw an image onto a canvas). Owned by Task 5 (its browser step).
4. **A name that is one letter once trimmed** (`"   R   "`): expected `displayNameTooShort`, not a saved one-letter name. Owned by Task 2 (its second test).
5. **An empty file** (the form submitted without JavaScript and without a file, or a forged request): expected `avatarMissing`, not a 500. Owned by Task 5 (its second upload test).

```ts
import { prisma } from "@/lib/db";

/**
 * User ids are cuids: letters and digits. Anything else is no user, and checking first
 * keeps a NUL byte from a crafted URL away from Postgres, which would throw (a 500).
 */
export function isUserId(id: string): boolean {
  return /^[a-z0-9]{1,40}$/i.test(id);
}

export type Relation = "friend" | "blocked" | "none";

/**
 * What viewerId is to userId, from the Friendship rows between them in either direction.
 * A block in either direction wins: D15, "blocking hides both directions".
 * The caller handles viewerId === userId (the profile's owner) before asking.
 */
export async function relationBetween(viewerId: string, userId: string): Promise<Relation> {
  const rows = await prisma.friendship.findMany({
    where: {
      OR: [
        { requesterId: viewerId, receiverId: userId },
        { requesterId: userId, receiverId: viewerId },
      ],
    },
    select: { status: true },
  });
  if (rows.some((row) => row.status === "BLOCKED")) return "blocked";
  return rows.some((row) => row.status === "ACCEPTED") ? "friend" : "none";
}
```

```ts
"use server";

import { refresh } from "next/cache";
import { z } from "zod";
import type { AuthErrorKey } from "@/lib/auth/schemas";
import { requireUser } from "@/lib/auth/session";
import { prisma } from "@/lib/db";
import { profileSchema, type ProfileFormState } from "@/lib/users/schemas";

/** Changes the caller's own display name. The id comes from the session, never from the form. */
export async function updateProfile(
  _prev: ProfileFormState,
  formData: FormData,
): Promise<ProfileFormState> {
  const ctx = await requireUser();

  const parsed = profileSchema.safeParse({ displayName: formData.get("displayName") ?? "" });
  if (!parsed.success) {
    return { fieldErrors: z.flattenError(parsed.error, (i) => i.message as AuthErrorKey).fieldErrors };
  }

  await prisma.user.update({
    where: { id: ctx.user.id },
    data: { displayName: parsed.data.displayName },
  });
  // Re-renders this page and the root layout's Nav, which shows the name.
  refresh();
  return { saved: true };
}
```

- [ ] **Step 2: Copy `sniffMime` from PR #35**

Create `src/lib/files/sniff.ts` (the body is `origin/correction`'s `documents/new/actions.ts` function, unchanged):

```ts
/**
 * The real type of a file, read from its first bytes; null when it is none of these.
 * Never trust file.type, which the client sets. Copied verbatim from Amir's upload action
 * (PR #35), so both uploads can share one sniffer: his action imports it from here.
 */
export function sniffMime(fileBuffer: Buffer): string | null {
  // PDF : %PDF
  if (fileBuffer.subarray(0, 4).toString("hex") === "25504446") {
    return "application/pdf";
  }
  // PNG : 89 50 4E 47 0D 0A 1A 0A
  if (fileBuffer.subarray(0, 8).toString("hex") === "89504e470d0a1a0a") {
    return "image/png";
  }
  // JPEG : FF D8 FF
  if (fileBuffer.subarray(0, 3).toString("hex") === "ffd8ff") {
    return "image/jpeg";
  }
  // WEBP : "RIFF" .... "WEBP"
  if (
    fileBuffer.length >= 12 &&
    fileBuffer.subarray(0, 4).toString("ascii") === "RIFF" &&
    fileBuffer.subarray(8, 12).toString("ascii") === "WEBP"
  ) {
    return "image/webp";
  }
  return null;
}
```

```ts
/** Stores the caller's avatar, replacing the previous one (one row per user). */
export async function uploadAvatar(
  _prev: AvatarFormState,
  formData: FormData,
): Promise<AvatarFormState> {
  const ctx = await requireUser();

  const parsed = avatarSchema.safeParse(formData.get("avatar"));
  if (!parsed.success) {
    return { error: parsed.error.issues[0]?.message as AvatarErrorKey };
  }

  // The bytes decide the type: a renamed SVG, HTML or PDF file is refused here.
  const data = Buffer.from(await parsed.data.arrayBuffer());
  const mimeType = sniffMime(data);
  if (!mimeType || !(AVATAR_TYPES as readonly string[]).includes(mimeType)) {
    return { error: "avatarType" };
  }

  await prisma.userAvatar.upsert({
    where: { userId: ctx.user.id },
    create: { userId: ctx.user.id, data, mimeType },
    update: { data, mimeType },
  });
  refresh();
  return { saved: true };
}
```

```ts
import { getCurrentUser } from "@/lib/auth/session";
import { prisma } from "@/lib/db";
import { isUserId } from "@/lib/users/profile";

// Any signed-in user may load any avatar: profiles are open to every signed-in user.
// The profile page, not this route, hides a profile across a block.
export async function GET(_request: Request, { params }: { params: Promise<{ id: string }> }) {
  // A Route Handler answers 401 instead of redirecting to /login.
  if (!(await getCurrentUser())) {
    return new Response(null, { status: 401 });
  }

  const { id } = await params;
  const avatar = isUserId(id) ? await prisma.userAvatar.findUnique({ where: { userId: id } }) : null;
  if (!avatar) {
    return new Response(null, { status: 404 });
  }

  return new Response(new Uint8Array(avatar.data), {
    headers: {
      "Content-Type": avatar.mimeType,
      // The bytes decided the type at upload; never let the browser guess another one.
      "X-Content-Type-Options": "nosniff",
      // PROJECT_PLAN §2: files are private and never cached.
      "Cache-Control": "private, no-store",
    },
  });
}
```

```tsx
"use client";

import { useTranslations } from "next-intl";
import { startTransition, useActionState, useState, type FormEvent } from "react";
import { Button } from "@/components/ui/Button";
import { AVATAR_TYPES, type AvatarFormState } from "@/lib/users/schemas";
import { uploadAvatar } from "./actions";

const initialState: AvatarFormState = {};
const SIDE = 256;

/**
 * Draws the picture, centre-cropped, onto a 256 × 256 canvas and returns it as a PNG.
 * A 3–12 MB phone photo becomes a few hundred KB (under the 2 MB cap), and its EXIF
 * metadata, GPS included, is dropped. Browsers apply the EXIF orientation when they draw,
 * so a portrait photo comes out upright. Null when the browser cannot decode the file.
 */
async function toSquarePng(file: File): Promise<File | null> {
  const url = URL.createObjectURL(file);
  try {
    const img = new Image();
    img.src = url;
    await img.decode();
    const side = Math.min(img.naturalWidth, img.naturalHeight);
    const canvas = document.createElement("canvas");
    canvas.width = SIDE;
    canvas.height = SIDE;
    canvas
      .getContext("2d")
      ?.drawImage(
        img,
        (img.naturalWidth - side) / 2,
        (img.naturalHeight - side) / 2,
        side,
        side,
        0,
        0,
        SIDE,
        SIDE,
      );
    const blob = await new Promise<Blob | null>((resolve) => canvas.toBlob(resolve, "image/png"));
    return blob && new File([blob], "avatar.png", { type: "image/png" });
  } catch {
    return null;
  } finally {
    URL.revokeObjectURL(url);
  }
}

export function AvatarForm() {
  const t = useTranslations("profile");
  const [state, formAction, pending] = useActionState(uploadAvatar, initialState);
  const [undecodable, setUndecodable] = useState(false);
  const errorKey = undecodable ? "avatarType" : state.error;

  // With JavaScript, the re-encoded PNG is sent instead of the original. Without it, the
  // form posts the original file and the server's checks still apply.
  async function onSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    const data = new FormData(event.currentTarget);
    const file = data.get("avatar");
    if (file instanceof File && file.size > 0) {
      const png = await toSquarePng(file);
      if (!png) {
        setUndecodable(true);
        return;
      }
      data.set("avatar", png);
    }
    setUndecodable(false);
    startTransition(() => formAction(data));
  }

  return (
    <form action={formAction} onSubmit={onSubmit} className="space-y-3">
      <label htmlFor="avatar" className="block text-sm font-medium text-zinc-700 dark:text-zinc-300">
        {t("avatar.label")}
      </label>
      <input
        id="avatar"
        name="avatar"
        type="file"
        accept={AVATAR_TYPES.join(",")}
        required
        aria-describedby="avatar-hint"
        aria-invalid={!!errorKey}
        className="block w-full text-sm text-zinc-700 file:mr-3 file:rounded-lg file:border-0 file:bg-zinc-100 file:px-3 file:py-2 file:text-sm file:font-medium hover:file:bg-zinc-200 dark:text-zinc-300 dark:file:bg-zinc-800 dark:hover:file:bg-zinc-700"
      />
      <p id="avatar-hint" className="text-xs text-zinc-500 dark:text-zinc-400">
        {t("avatar.hint")}
      </p>
      {errorKey ? (
        <p role="alert" className="text-sm text-red-600 dark:text-red-400">
          {t(`errors.${errorKey}`)}
        </p>
      ) : state.saved ? (
        <p role="status" className="text-sm text-green-700 dark:text-green-400">
          {t("avatar.saved")}
        </p>
      ) : null}
      <Button type="submit" disabled={pending}>
        {pending ? t("avatar.pending") : t("avatar.submit")}
      </Button>
    </form>
  );
}
```
